REDLINE UPGRADE — PHASE 13.5
VISUAL / TERMINOLOGY / FEEDBACK CLEANUP

This is a focused cleanup phase.

Do NOT add new gameplay mechanics.

Preserve all existing Phase 8–13 systems.

==================================================
1. CPU CARD DRAW PRESENTATION
==================================================

When a CPU player draws a card, show the card prominently to ALL players.

The card should:

- Appear substantially larger than the normal card UI
- Be centered/prominent on the screen
- Show the deck
- Show the card name
- Show the card artwork
- Show the card effect
- Clearly identify which CPU drew it

Keep the card visible long enough for players to actually read it.

Do not immediately resolve and disappear.

Use a short presentation sequence:

CPU ACTION
→ CARD REVEAL
→ CARD EFFECT
→ RESULT

The same presentation system should work for human and CPU players.

Do not create separate card-resolution logic for CPU players.

==================================================
2. AUDIT ALL MILESTONE ASSET ARTWORK
==================================================

Audit EVERY milestone asset.

Categories:

- CAR
- LIFESTYLE
- PET
- INVESTMENT
- PROPERTY

There should be 20 available assets per milestone category.

Each asset must have actual unique artwork.

DO NOT use generic placeholder icons as the final artwork.

The screenshot currently shows newer assets using generic car/icon placeholders. Replace those wherever the actual unique asset artwork exists or create/identify the correct asset artwork reference.

Also audit all upgraded versions.

Every asset should support:

LEVEL 1
LEVEL 2
LEVEL 3
LEVEL 4

where applicable.

Each level must use the correct visual for that asset.

Example:

HOLODOG LVL 1
→ Level 1 artwork

HOLODOG LVL 2
→ Level 2 artwork

HOLODOG LVL 3
→ Level 3 artwork

HOLODOG LVL 4
→ Level 4 artwork

Do not display a generic icon when a specific asset image exists.

==================================================
3. MILESTONE IMAGE VALIDATION
==================================================

Create an automated/content audit where possible.

For every milestone asset verify:

- Asset ID

- Image actually exists

- Image displays correctly in the card
- Image displays correctly in milestone selection

Report any remaining missing artwork.

Do not silently substitute unrelated artwork.

==================================================
4. CONSISTENT TERMINOLOGY
==================================================

Audit the entire game for inconsistent terminology.

Choose ONE term for each concept and use it everywhere.

Pay particular attention to:

- Wealth
- Salary
- Salary Tier
- Career
- Career Category
- Career Deck Affinity
- Upgrade Token
- Milestone
- Asset
- Asset Level
- Finish
- Finish Bonus
- Card Deck

The current "career affinity" terminology can be confusing.

Use a clearer player-facing label.

Preferred direction:

CAREER DECKS

or

BONUS DECKS

The underlying code can continue using "affinity" if useful.

Player-facing UI should explain the mechanic clearly.

Example:

CAREER DECKS
AI SKILL • WEALTH

"Matching these decks can trigger your career bonus."

Keep the explanation short.

==================================================
6. CARD RESOLUTION SHOULD NOT FEEL INSTANTANEOUS
==================================================

Make card resolution feel like an actual board-game moment.

Sequence:

1. Player lands
2. Space is identified
3. Card is revealed
4. Card remains readable
5. Effect is announced
6. Ability interactions resolve
7. Final result is shown
8. Turn continues

Do not remove the card immediately after drawing it.

Allow enough time for players to understand what happened.

Human and CPU cards use the same presentation framework.

==================================================
7. DISABLED ACTIONS MUST EXPLAIN WHY
==================================================

Any disabled button/action should communicate the reason.

Bad:

[UPGRADE] (disabled)

Better:

[UPGRADE]
"Requires Upgrade Token"

Examples:

"Not enough Wealth"
"Already owned"
"Ability already used this turn"
"No eligible asset"
"Must reach milestone first"
"Cannot use during this phase"

Do not create vague disabled controls.

==================================================
8. SALARY TIER VISUAL SYSTEM
==================================================

Make salary tiers much more visually distinct.

Use increasingly strong color treatment.

LOWEST salary tier:
Strong red/dark red treatment

LOW salary tier:
Orange/red

STANDARD/MID:
Neutral/dark treatment

HIGH:
Gold

HIGHEST:
Bright gold / premium gold treatment

Gold should clearly communicate the highest salary tier.

Red should clearly communicate the lowest salary tier.

Use subtle shading, borders, labels, and accents rather than filling the entire player card with bright colors.

The salary tier should remain visible on:

- Career card
- Player card
- Career selection
- Any relevant salary display

==================================================
9. CAREER CARD COLORS

Career cards should have visual identity based on their deck affinities.

Each career has primary and secondary deck affinities.

Make those affinities visually obvious on the career card.

Example:

AI ENGINEER

CAREER DECKS
[AI SKILL] [WEALTH]

The career card should use subtle visual accents associated with those decks.

Do NOT make the entire career card two unrelated bright colors.

Use:

- Small affinity badges
- Accent borders
- Subtle background gradients
- Deck icons
- Small color strips

The player should be able to understand:

"This career is connected to these decks."

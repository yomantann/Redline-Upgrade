REDLINE UPGRADE — PHASE 10

Build the Upgrade Token system and expand the existing milestone asset system.

Use the existing Phase 8/9/9.5 event architecture, card system, career system, milestone system, player cards, and UI.

Do NOT redesign or replace existing systems.

==================================================
1. UPGRADE TOKEN PURPOSE
==================================================

Upgrade Tokens are a simple, scarce resource with exactly 3 possible uses:

1. UPGRADE an existing milestone asset
2. RECOVER a missed milestone asset
3. HOLD the token for the endgame

Do NOT create new stats, currencies, complicated passive abilities, or another progression system.

Upgrade Tokens should be temporary to the current game.

They are NOT persistent profile inventory.

==================================================
2. UPGRADE TOKEN ACQUISITION
==================================================

Create 3 acquisition methods.

A. CARD DECKS

Add exactly ONE unique Upgrade Token card to each of the 6 existing decks:

- WEALTH
- AI SKILL
- FAME
- LIFESTYLE
- INFLUENCE
- GAMBLE

Each card should:

- Have unique artwork
- Have unique flavor/bio text
- Clearly identify that it grants 1 Upgrade Token
- Use the existing card UI
- Have the same core mechanical result:

GAIN 1 UPGRADE TOKEN

Do not create six different token mechanics.

The cards should feel different thematically based on their deck.

B. CAREER

Assign exactly ONE existing career a starting benefit:

START WITH 1 UPGRADE TOKEN

Use the existing career ability/starting-benefit architecture.

Do not create a new career system.

C. BOARD

Add exactly TWO Upgrade Token spaces to the 75-space board.

They should:

- Have a unique color
- Have a clear Upgrade Token icon
- Be visually distinct from other space types
- Fit the existing board visual style

Landing on an Upgrade Token space:

GAIN 1 UPGRADE TOKEN

Do not create a special penalty or additional effect.

==================================================
3. PLAYER STATE
==================================================

Add a clear upgrade-token count to the player state.

Example:

upgradeTokens: number

This should be included in the existing Player/Game state architecture.

It must work for:

- Human players
- CPU players
- Future multiplayer

Do not create a separate resource system.

==================================================
4. PLAYER CARD UI
==================================================

Clearly display Upgrade Tokens on every player's player card.

Example:

UPGRADE TOKENS
🔧 🔧 🔧
3 HELD

The count should update immediately when tokens are gained or spent.

Other players should be able to see the number of Upgrade Tokens a player is holding.

This is intentional because holding tokens for the endgame should create visible tension.

==================================================
5. BEGINNING-OF-TURN UI
==================================================

Players can use Upgrade Tokens ONLY at the beginning of their own turn.

Place an Upgrade button near the existing dice roll button.

Example:

🔧 USE UPGRADE (3)

🎲 ROLL 2D4

If the player has 0 Upgrade Tokens:

🔧 USE UPGRADE (0)

The Upgrade button should be disabled.

The player must be able to clearly see that they have Upgrade Tokens before rolling.

Do not allow Upgrade Tokens to be used in the middle of movement, card resolution, milestone resolution, or another player's turn.

==================================================
6. UPGRADE MENU
==================================================

When the player chooses USE UPGRADE, present exactly these options:

A. UPGRADE ASSET

B. RECOVER MILESTONE

C. HOLD

The menu should clearly explain each option.

==================================================
7. UPGRADE ASSET
==================================================

If the player chooses UPGRADE ASSET:

Show only milestone assets that the player currently owns and that are eligible for upgrading.

Each asset has:

LEVEL 1
LEVEL 2
LEVEL 3
LEVEL 4

Level 1 is the original milestone asset.

Each Upgrade Token increases the selected asset by exactly 1 level.

The upgrade is FREE.

No Wealth cost.

Maximum level is Level 4.

Example:

HoloDog
Level 1
↓ Upgrade Token
Level 2
↓ Upgrade Token
Level 3
↓ Upgrade Token
Level 4

Each upgrade should update:

- Asset level in game state
- Player card visual
- Asset description/effect where applicable
- Any existing milestone/asset calculations

Do not create complicated new abilities for each level.

The primary purpose is to make the existing asset progressively better/more valuable.

==================================================
8. RECOVER MILESTONE
==================================================

IMPORTANT:

The player does NOT get to choose the recovered asset.

If the player chooses RECOVER MILESTONE:

1. Determine which milestone categories the player has already PASSED.
2. Exclude any milestone that the player has not yet reached.
3. Exclude milestone assets/categories that cannot legally be recovered.
4. Randomly select ONE eligible milestone category.
5. Randomly assign ONE eligible asset from that milestone category to the player.
6. The asset is FREE.
7. Consume exactly 1 Upgrade Token.

There is NO choice screen for the player.

The player should see a reveal animation/UI showing what they randomly recovered.

Example:

UPGRADE TOKEN USED

RECOVERED MILESTONE:
PET

YOUR RANDOM ASSET:

🐕 HOLODOG
LEVEL 1

ACQUIRED FREE

The player should not be able to select between multiple assets.

This is intentionally a random second chance.

==================================================
9. MILESTONE ELIGIBILITY
==================================================

A player can only recover a milestone AFTER they have passed that milestone on the board.

Example:

If the player has passed:

CAR
LIFESTYLE

but has not yet passed:

PROPERTY

Then Recover Milestone can only randomly recover:

CAR
or
LIFESTYLE

It cannot give PROPERTY.

Do not allow Upgrade Tokens to provide future milestones early.

Existing milestone ownership rules should be preserved.

==================================================
10. RECOVERED ASSETS
==================================================

A recovered asset begins at LEVEL 1.

The player may later use additional Upgrade Tokens to upgrade it normally.

Example:

Player passes Pet milestone without getting a pet.

Later:

Upgrade Token → Recover Milestone

Random result:

HoloDog Level 1

Later:

Upgrade Token → Upgrade Asset

HoloDog Level 2

==================================================
11. HOLDING TOKENS
==================================================

If the player chooses HOLD:

Do nothing.

Do not consume a token.

The player continues their turn normally.

Held Upgrade Tokens must remain visible on the player card.

The game must track how many Upgrade Tokens remain unused at all times.

However, prepare the game state so the future endgame can read:

upgradeTokens

and specifically:

unused/held Upgrade Tokens at the moment the player enters the endgame.

The future endgame will use the number of held Upgrade Tokens to significantly enhance the player's selected:

- CASH OUT
- DOUBLE DOWN
- GAMBLE

choice.

For Phase 10, only make sure the information is preserved and available.

Do not invent final endgame formulas yet.

16. ASSET UPGRADE EFFECTS
==================================================

Keep effects simple.

- Increase an existing benefit

The Upgrade Token system should remain easy to understand.

==================================================
17. CPU PLAYERS
==================================================

CPU players must support Upgrade Tokens.

CPU behavior can be simple.

At the beginning of a CPU turn:

If the CPU has an Upgrade Token, allow a basic deterministic decision such as:

- Upgrade an owned eligible asset if one exists
- Otherwise recover a previously passed milestone if eligible
- Otherwise hold

Do not create complex AI strategy.

The important requirement is that CPU players correctly maintain and spend Upgrade Tokens without breaking the game.
